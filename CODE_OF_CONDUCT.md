# Code of Conduct

## The short version

Be respectful. Be direct. Focus on the work. Do not make this community hostile to participate in.

---

## Expected behaviour

- Communicate clearly and assume good faith.
- Accept that maintainers may decline contributions, request significant changes, or close issues without extended discussion.
- Give and receive feedback about code, not about the person writing it.
- Respect maintainer decisions about project scope and direction — this is their project, not a committee.
- If you disagree with a decision, state your case once, clearly. Do not campaign, relitigate, or escalate.

---

## Unacceptable behaviour

- Harassment, personal attacks, or hostile communication of any kind.
- Derailing issues and PRs with unrelated arguments.
- Repeatedly pushing declined contributions.
- Publishing others' private information.
- Any behaviour that makes the project an unwelcoming place to contribute to.

---

## Scope

This applies to all project spaces: GitHub issues, pull requests, discussions, code comments, and any other project-related communication.

---

## Enforcement

The maintainer handles enforcement. Reports go to the maintainer's contact listed in [SECURITY.md](./SECURITY.md) (or directly via email if the project provides one).

Consequences range from a request to change behaviour through to a permanent ban from the project, at the maintainer's discretion.

The maintainer is under no obligation to explain enforcement decisions publicly.

---

## Note for projects with larger teams

If your project grows to multiple maintainers, replace the single-maintainer enforcement model above with a defined moderation team and a documented escalation path.
